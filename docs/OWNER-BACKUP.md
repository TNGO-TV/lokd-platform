# Owner production backup

The read-only `/api/internal/owner-backup` endpoint is disabled by default. Set `LOKD_BACKUP_ENABLED=true`, a SHA-256 verifier in `LOKD_BACKUP_TOKEN_SHA256`, and an epoch-millisecond `LOKD_BACKUP_EXPIRES_AT` no more than one hour ahead. Supply the private 32-byte hexadecimal credential only in `x-owner-backup-token`. Browser-origin requests and non-POST requests are denied. Remove these settings and redeploy after capture; expiry independently closes access.

The runtime export is restricted to the ten application keys configured at revision 9. Update that explicit list if application configuration changes. It excludes platform credentials. All capture output must stay private; never commit controls, exported configuration, data, or archives.

`scripts/owner-backup-capture.py` accepts `--url`, `--control`, `--key`, and a new `--output` directory. The private JSON control has `token` and `expected_runtime_keys`. Reuse the established separate backup encryption key. The script captures all object pages and conditional version-matched bytes, takes one transactional D1 snapshot, verifies unchanged inventory and database object references, restores into an empty SQLite database, compares schema/storage classes/cells, checks integrity and foreign keys, encrypts the capture, then decrypts and checks file hashes.

The snapshot is bounded to 200 tables, 100 columns per table, 20,000 rows and 4 MiB of encoded cells, divided across query groups of at most four tables. It rejects virtual tables and unsupported row-ID layouts; it returns an explicit error for excess size. Cloudflare `_cf_` internal tables are excluded and named in the receipt. Generated column values are verified after recomputation. Provider internals are regenerated by the destination platform.

A successful application capture is not by itself full disaster recovery. External Clerk identity, Paystack and VerifyNow recovery records, source/release receipts, endpoint revocation and an independent off-host copy require separate evidence. The verification receipt intentionally starts with `full_production_recovery_complete=false`.

Run `node scripts/check-owner-backup-runtime.mjs` with local loopback permission for the 31-table wide-schema D1/R2 and Python restore check.

Validation: SQLite edge-case restore tests, actual local D1/R2 runtime metadata and byte checks, full application regression suite, TypeScript check and production build. Production capture and revocation must be independently recorded; this document does not claim they occurred.
