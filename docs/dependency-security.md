## Unpatched build-only parser

[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) affects braces through 3.0.3 when an attacker supplies deeply nested patterns. The npm registry's latest braces version remains 3.0.3 on the review date. npm's proposed automatic fix downgrades framework/tooling majors and is not a compatible fix.

In this project the parser is only in development dependency chains: ESLint's Next plugin and Vinext's build-time CommonJS/dynamic-import scanning, through fast-glob and micromatch. Inputs are checked-in lint globs, source import patterns and project filenames. HTTP request bodies, uploaded documents, query strings and database fields are not inputs to these build/lint tools. CI builds the proposed source in an isolated runner without application secrets; it necessarily executes that same proposed source's scripts. The production Worker does not run ESLint or a Vite dev server.

This is a narrowly bounded non-applicability disposition, not a claim that braces is patched. `build/dependency-boundary.ts` fails a build if braces, micromatch or fast-glob appears in any emitted client/server chunk's module graph or external imports. It writes per-environment graph hashes into private test-results. `scripts/check-dependency-audit.mjs` permits only this exact advisory at the single development-only lockfile path and version, until 2026-11-16. New advisories, runtime placement, versions, paths, malformed audit output and audit transport/process errors fail the gate. Full raw findings remain in the candidate evidence; nothing is hidden by excluding development dependencies from the full gate.

If these parsers become runtime dependencies or build patterns start accepting public input, this disposition no longer applies. A patched upstream release should replace it when available, with a fresh audit and full validation.
