# Public intake receipts and rollout

Client enquiries (0084) and Officer applications (0086) retain independent submissions, including separate submissions with identical contact details. Contact data never deduplicates a submission or grants ownership. A caller may provide a random UUIDv4 submission key. The server stores only a domain-separated key hash and normalized payload hash, atomically with the new source record and its audit event. An identical keyed retry returns the original saved receipt. Reusing a key with different normalized facts returns409 without disclosing the earlier reference. Concurrent retries roll back losing copies; a lost batch acknowledgement recovers the committed receipt.

The public forms lock synchronously while sending, require saved:true with a full action-specific UUID reference, and keep the original body/key in the current tab after an uncertain result. A neutral anti-spam202, malformed body or generic success never claims saving. The retry button resends only that original body. After a definite rejection, identical input retains its key; editing the submission creates a fresh key. No sensitive draft is written into browser persistent storage. Closing the tab loses this recovery material. The isolated sandbox retains its separate guarded command recovery protocol and also requires a genuine saved receipt.

Migration0086 creates only an immutable receipt table and its guards. It changes no existing application, consent, identity, audit or account-link record. The three Officer consents, pathway-specific PSiRA checks and verified-email ownership rules remain mandatory. Requests from older clients without a key remain independent; they cannot recover a lost acknowledgement.

Deploy migrations through0086 before these handlers. Migration execution requires separate release authorization. Preserve receipt tables and hashes when rolling forward; rolling back to handlers without keyed recovery would reintroduce duplicate uncertain submissions. Do not delete existing receipt history as a rollback. No live migration was performed for this work.
